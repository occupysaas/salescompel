# Plan 20 — Flow execution feasibility

Status: proposed for maintainer review, 2026-11-03. Specification and implementation planning only; no Flow runtime, fixtures or verification results delivered yet.

## Intent and selection

Determine whether an independently implemented executor can consume a small, explicit Flow metadata XML subset unchanged, follow its connectors rather than fixture-specific code, mediate all record access through a host, discard staged changes on failure and terminate cyclic graphs predictably. Publish a reproducible continue/revise/blocked decision before choosing a general Flow architecture.

[Plan 17](../../compat/plan-17-target-inventory.md) still supplies an inventory format rather than a real target inventory. ## Exact accepted source boundary

Parse one UTF-8 XML document whose root is `Flow` in namespace `http://soap.sforce.com/2006/04/metadata`. Compare full expanded XML names, not just local names. Namespace declarations are allowed only on the root; other attributes are rejected. Whitespace, comments and one initial XML declaration are allowed. Reject DTD/directives, other processing instructions, custom entities, trailing roots, mixed non-whitespace text in containers and unsupported encodings. Built-in XML entities/character references decode normally. Reject unknown elements/attributes and duplicate singleton children anywhere, including unreachable nodes. Do not silently skip unfamiliar metadata.

The root requires exactly one each: `apiVersion=65.0`, nonempty `label`, nonempty `interviewLabel`, `processType=AutoLaunchedFlow`, `status=Draft`, and `start`. It allows repeated `variables`, `assignments`, `decisions`, `recordLookups`, `recordUpdates`, and optional `description`. Root child order is immaterial; order within rules and assignment items is meaningful. `Active`, record-triggered starts, legacy start-element references and other process types are unsupported, not interpreted as the chosen mode. This executes draft synthetic fixtures offline; it makes no deployment/activation claim.

Every named resource uses ASCII `[A-Za-z_][A-Za-z0-9_]*`; names are case-sensitive. Variables and executable nodes share a unique namespace; rules have unique names within their decision. References and connectors must resolve exactly before host begin, even if unreachable. A connector contains exactly one nonempty `targetReference` naming an executable node. Missing optional connectors terminate successfully; a present empty/dangling connector is invalid. Start requires one connector and optionally `locationX`/`locationY`; it cannot carry trigger, schedule, object or filter configuration.

Every executable node requires `name` and `label`, permits optional `description`, `locationX`/`locationY` (signed int32 decoration only), plus only the children below. Labels/descriptions/locations never affect dispatch. Unknown decorative fields are rejected too. Publish a complete cardinality/type allowlist in the results guide before executor implementation; no implicit decoder defaults may enlarge this boundary.

| Construct | Accepted children and restrictions |
| --- | --- |
| `variables` | `name`, `dataType` (`String` or `Boolean`), explicit `isCollection=false`, explicit `isInput`, explicit `isOutput`; optional `description`, and `value` containing one matching literal. No record/collection/number variables, formulas or reference-valued defaults. |
| `assignments` | One or more ordered `assignmentItems` and optional `connector`. An item contains `assignToReference` naming a scalar variable, `operator=Assign`, and `value`. No property assignment, arithmetic, string templates or collection operations. |
| `decisions` | One or more ordered `rules`, required `defaultConnectorLabel`, optional `defaultConnector`. A rule requires `name`, `label`, `conditionLogic=and`, one or more ordered `conditions`, optional `connector`. A condition contains `leftValueReference`, `operator` and `rightValue`. Support `EqualTo` on same-type String/Boolean scalars and `IsNull` with a Boolean right value on String/lookup resources. No custom logic expression. |
| `recordLookups` | `object=Account`, exactly one `filters`, `getFirstRecordOnly=true`, `storeOutputAutomatically=true`, optional `connector`. No outputReference/outputAssignments, explicit queried fields, sorting, limit, faultConnector or assignNullValuesIfNoRecordsFound. The node name exposes a private single-record resource. |
| `recordUpdates` | `object=Account`, exactly one `filters`, exactly one `inputAssignments` (`field=Name`, scalar String `value`), optional `connector`. No inputReference, faultConnector or other write field. This is a filtered bulk update, not a record-variable update. |
| `filters` | `field=Probe_Group__c`, `operator=EqualTo`, `value` resolving to String. No external-ID matching, multi-condition filtering or general query syntax. |
| `value` / `rightValue` | Exactly one of `stringValue`, `booleanValue` (`true`/`false`), or `elementReference`. Scalar references name a variable or `<lookupName>.Id`, `.Name`, `.Probe_Group__c`. Whole lookup names are allowed only as the left operand of IsNull. No expression evaluation, interpolation, `$` globals or arbitrary member chains. |

All required booleans use lowercase true/false; empty String literals are allowed. Whitespace around identifier/enum/Boolean/numeric leaf text is ignored; String literal bytes after XML decoding are preserved. Missing String defaults are Null, missing Boolean defaults false. This defaulting is a synthetic rule. Every `isInput=true` variable must be supplied exactly once via the harness map with matching type; unknown/non-input keys, missing required inputs and Null Boolean inputs fail before begin. String inputs may be Null. Before copying caller inputs, reject a map larger than Variables and validate scalar String sizes/UTF-8; capture the bounded map and policy denial list before any observer callback. After compilation, validate exact keys/types against declarations before begin. Inputs are copied; assignments may change invocation-local input variables. Every `isOutput=true` variable appears in the successful detached output map, including default/unassigned values. Errors return a zero result with no outputs or usage.

Compile validates the complete XML, node/variable names, supported operators, reference types and connector targets before any host activity. It does not prove definite execution of a lookup before a reference. An unexecuted or empty lookup's field dereference fails at runtime; IsNull on an executed empty lookup returns true, while an unexecuted lookup resource is a runtime error. Scalars compare by exact UTF-8 bytes or Boolean value; String Null equals String Null, and is distinct from empty String. Ordered decision rules choose the first true rule; AND conditions short-circuit. Assignments evaluate items sequentially and see earlier item updates. Cycles among supported nodes are permitted by this synthetic graph model and executed iteratively under the step budget; this is not a claim that Salesforce accepts arbitrary cyclic deployments. FlowLoop and collection iteration remain unsupported.

## Host, effects and controls

Each run receives explicit tenant/principal, typed scalar inputs, positive finite limits and a trusted synthetic Account store. Account contains Tenant, ID, Cohort and Name; Cohort models only synthetic `Probe_Group__c`. Queries filter tenant and exact cohort and use ascending ID as a deterministic synthetic order. Lookup selects at most the first match. A filtered update selects all matches through the same host query boundary and stages Name changes through invocation-bound capabilities. It requires both query permission and Name-write permission; denied IDs are tenant-local. Null cohort filters and Null Name values fail with `runtime` at the executing node before query/stage; they neither match empty strings nor become empty writes. Evaluate both update operands before selection, so a Null Name fails even with no matching records. Any earlier staged effects still roll back. Zero matching rows is a successful empty update for an allowed principal; operation permission is still checked. No administrator bypass or real Flow execution security mode is implied.

Only the host can access records or commit. Copy policy lists, store input, snapshots and returned records; no alias may mutate committed state. Queries observe earlier staged Names. Validate a whole bulk batch before staging it. A denied later row, error after an earlier update, budget failure or cancellation discards the entire invocation. A failed or finalized transaction cannot commit or be reused. Publish one new complete snapshot only after successful graph termination, output validation and a final cancellation/budget checkpoint. Concurrent invocations require separate stores; shared-store isolation/concurrency is unsupported.

Defaults: XMLBytes=65536, XMLDepth=32, XMLTokens=16384, Nodes=64, Variables=32, Steps=2000, Rows=100, Writes=100, StringBytes=4096. Every limit must be positive. Nodes counts executable assignment/decision/lookup/update nodes only; start and rules are not executable nodes for this counter. Variables counts declared scalar variables. StringBytes bounds decoded leaf text (including names/labels/literals) and evaluated/input/host strings; comments and namespace declaration storage are bounded by XMLBytes/XMLTokens instead. Check XML byte size before decoder creation, token/depth/string limits before retaining decoded tokens/text, node/variable limits before graph insertion, and row/write limits before materialization/staging. Tokens include every decoder token, including whitespace/comments. Steps charge before each node visit, assignment item, decision condition, host row scan/stage and commit row copy/publication checkpoint; Rows count all selected rows, including update selection, cumulatively; Writes count each submitted row per update, including repeated IDs across statements. A bulk statement may not contain duplicate IDs. No public collections beyond a bounded outputs map exist; a host selection is bounded by remaining Rows, and staged keys by Writes. Use overflow-safe remaining-budget comparisons. No recursive graph traversal/execution or hidden unmetered cycle may bypass these controls.

Cancellation must be checked before parsing, between XML tokens, at compile graph loops and all execution/host checkpoints, including just before publication. Count steps only for execution/host work; compilation uses the XML/node/variable limits. Use an invocation-local private event observer in tests for deterministic cancellation after staging and before commit; no sleeps, global hooks or evaluated-source hooks. There is no atomic guarantee against cancellation racing after the last publication check, and no cancellation guarantee inside a Go allocation. Trusted store/policy sizes and caller-selected limits are not a production heap sandbox. No source may invoke filesystem, network, process, wall-clock, environment, Apex or external actions.

Diagnostics expose a stable code, phase and byte offset, never source text, variable values or raw XML parser errors. Codes: `invalid-input`, `syntax`, `unsupported`, `invalid-graph`, `type`, `runtime`, `denied`, `budget`, `cancelled`. Phases: `input`, `xml`, `graph`, `execute`, `commit`. Input errors use offset -1; source-bound phases use an offset within the original source; commit errors use the Flow root opening-token offset with phase commit. Empty/oversized/invalid-encoding source errors use xml offset 0. Malformed XML/encoding uses syntax; unknown namespace/element/attribute/operator/mode/version uses unsupported; missing/duplicate required children, invalid names and dangling/malformed references use invalid-graph; incompatible declared scalar types use type. These are experiment diagnostics, not Salesforce wire errors. Plan 19's deferred finalization-location finding stays deferred there; do not silently change its results or implementation.

## Mandatory experiment matrix

| Experiment | Required assertion |
| --- | --- |
| Graph execution | The same XML bytes with varied Boolean/String inputs choose true/default/first-of-two-matching rules, run ordered assignments and yield exact scalar outputs. Labels/locations cannot alter dispatch. |
| Record workflow | One XML graph performs Get Records, branches on missing/existing lookup or a selected Name, assigns a local value and bulk-updates the cohort. Run empty/one/multiple rows, same local IDs across tenants, allowed/denied principals. Compare every store field and exactly one success commit. |
| Read-your-writes | One graph updates, re-queries and exposes the staged Name before final commit; no committed state changes early. |
| Rollback | Stage an earlier update, then encounter a late denied batch row, Null field dereference, exhausted budget or cancellation. Trace staged/discard and compare the complete store to its initial snapshot. |
| Whole-source validation | Unknown or wrong-namespace elements/attributes, duplicate singleton/name, unsupported action/formula/FlowLoop/faultConnector/screen/trigger, dangling connector/resource, incompatible type/operator and extra XML root all fail before host begin, including in disconnected nodes and untaken branches. |
| Bounded input and execution | Exact/over XML bytes/depth/tokens/nodes/variables/String bytes and cumulative steps/rows/writes; cyclic graph controlled budget failure, including after staging. Reject nonpositive limits; no panic or partial commit. |
| Cancellation | Before work, during token/graph processing, after staging and immediately before commit; deterministic synchronization and no partial effects. |
| Repeatability and isolation | Run every deterministic scenario twice with fresh state and unchanged XML hash; concurrent identical XML on separate stores shares neither variables, lookup resources, identity nor budgets. Mutating input maps, policy lists or snapshots cannot alter owned state. |
| Diagnostic honesty | Stable code/phase/offset for malformed input, unsupported/disconnected nodes, host denial, execution errors and finalization failures; no source/values in error text. |

Each mandatory case must have a real assertion and recorded actual outcome, fixture, command and basis. JSON expected values are not measurements. Keep source-informed shape, synthetic semantics, implementation and verification distinct; reference observations are none.
