# Plan 21 — Imported UI hosting feasibility

Status: proposed for maintainer review, 2026-11-03. Specification/planning only; no imported component runtime or browser experiment implemented.
Milestone: bounded M7 feasibility work; full M7 remains open.

## Intent and selection

Test whether independently authored LWC-shaped HTML, JavaScript and metadata can remain unchanged as inputs while a small independent interpreter renders a real browser component, handles edits/events and accesses records only through an explicit synthetic host. Deliver an executable source-to-browser experiment and a reproducible Continue/Revise/Blocked decision, rather than translating each fixture into Vue by hand.

The [roadmap](../../plans/2026-10-14-salesforce-compatibility-roadmap.md#proposed-architecture) explicitly distinguishes native Vue UI from imported LWC/Aura/Visualforce. Its [recommended sequence](../../plans/2026-10-20-progress-and-remaining-roadmap.md#recommended-sequence) calls for early imported UI feasibility. [Plan 19](../../compat/plan-19-apex-execution-feasibility.md) completed a bounded Apex experiment; [Plan 20](2026-11-03-plan-20-flow-execution-feasibility-design.md) is planned, not executed. Plan 21 is independent of the unimplemented Flow package. Neither numbering nor planning closes a milestone. Plan 17 still lacks a real target inventory.

LWC-shaped source, a deliberately tiny interpreter and a separate developer harness are executor recommendations, not accepted customer coverage. Alternatives include choosing an eligible existing runtime or starting with Aura/Visualforce; this package first tests source handling, rendering and host routing without licensing a new runtime or pretending Vue executes imported components automatically. It cannot establish broad LWC feasibility, actual Salesforce semantics or sufficient real-target coverage. Full JavaScript execution and a production hostile-component sandbox remain separate architectural questions.

## Deliverables and isolation

1. An isolated TypeScript experiment under `web/compat/imported-ui/`: complete bundle parsers, immutable source model, bounded scalar interpreter, safe DOM renderer, synthetic host and developer harness.
2. Independent three-file fixtures and scenario inputs, unit tests plus a dedicated Playwright browser suite using the existing toolchain.
3. `docs/compat/plan-21-imported-ui-hosting-feasibility.md`: exact grammar/allowlists, source ledger, actual results, architecture decision and owned follow-ups.

No native UI route, Pinia store, production component, API/database/catalog, accepted profile/readiness/evidence, localization catalog, Plan 19 package/report or Plan 20 documents may change. Native product code must not import the experiment. New test/config files may live under web, but production build entry points remain byte-identical. Use a separate loopback-only Vite root and port 4181 with no product API proxy, no hosted deployment or end-user import/upload flow. All component source stays inert text: no eval, Function constructor, dynamic/module import of fixture JS, script/blob execution, raw HTML injection, DOMParser, or iframe executing imported source. Parse and interpret an explicit language subset; do not strip decorators and execute the remainder.

Native shadow DOM supplies rendering/style separation only, not a security boundary. Host policy and records are synthetic client-side harness data, not authoritative tenancy/authentication. The experiment must say so. Do not claim protected execution of arbitrary JavaScript or untrusted components.

## Accepted bundle and language

A bundle is exactly three supplied UTF-8 strings named `<name>.html`, `<name>.js`, `<name>.js-meta.xml`; bundle names are lower camel-case ASCII. No filesystem paths, ZIP extraction, CSS, SVG, extra files or nested components. Source bytes are preserved and hashed; the same parsed bundle is used for varied records/inputs. Dispatch must follow parsed fields/methods/template bindings, never bundle names or hard-coded DOM for a fixture.

Metadata: one `LightningComponentBundle` root in `http://soap.sforce.com/2006/04/metadata`, one each `apiVersion=65.0`, `isExposed=true`, and `targets` containing exactly `target=lightning__RecordPage`. A root default namespace declaration and optional initial XML declaration/whitespace are allowed. Reject unknown/duplicate elements, other attributes/namespaces, DTD/entities beyond built-ins/numeric character references, trailing roots, other targets and configurations. Do not use a permissive browser XML/HTML parser that silently discards unsupported content.

JavaScript: require exactly `import { LightningElement, api } from 'lwc';`, then one `export default class Identifier extends LightningElement { ... }`. Identifiers use ASCII `[A-Za-z_][A-Za-z0-9_]*`; reserve constructor, prototype, __proto__, dispatchEvent, and the imported symbols against member declarations. Fields require single-quoted String literal initializers and semicolons, with optional `@api`; public and private fields share a unique member namespace with methods. No getters/setters/static members, further imports, exports, types, inheritance, other decorators, expressions, conditionals, loops, calls or globals. Other lifecycle names (render, renderedCallback, disconnectedCallback, errorCallback) are unsupported even if unused.

Methods have either no parameters or one parameter named `event`. Optional `connectedCallback()` runs once at initial mount, has no parameters and cannot dispatch events. Other methods may contain only these statements, in source order:

```text
this.<privateField> = <value>;
this.dispatchEvent(new CustomEvent('save', { detail: <value> }));
value := single-quoted-string | this.<declaredField> | event.target.value
```

No assignment to public fields. `event.target.value` is allowed only inside a one-parameter method used by an input binding; it is a bounded String snapshot, never a DOM object. String escapes are only quote/backslash; no raw line breaks, interpolation or implicit conversion. Whitespace and `//` line comments are accepted; block comments and all other syntax are rejected. All methods, including unused ones, must be fully validated before host access or DOM mount. Duplicate/unknown fields, methods or references are invalid. A click handler must have no parameters; an input handler must have the one event parameter. No source can call another method, recurse or obtain ambient objects.

HTML: one outer `<template>` without attributes, containing text and only `section`, `h2`, `p`, `span`, `label`, `input`, `button`. Lowercase explicit tags only; input is void, with either `>` or `/>`, and other tags require matching closing tags. No nested template, script/style/URL-bearing elements, comments, directives, slots, loops or conditionals. Attributes are only literal double-quoted `class`, `title`, `aria-label`; `type="text"` on input or `type="button"` on button; `value={field}` and `oninput={method}` on input; `onclick={method}` on button. Literal value attributes or handlers are unsupported. Other attributes, duplicate attributes and mixed/expression-valued attributes are rejected. Text permits `{declaredField}` bindings only, mixed with literal text; no arbitrary expressions or member access. Parse bindings before decoding text entities so encoded braces remain literal. Decode only built-in entities and valid Unicode scalar numeric references; reject custom entities/NUL. A literal `{` or `}` in text must be entity-encoded. No raw imported markup enters live DOM.

Publish a full independent EBNF/cardinality/allowlist before interpreter work. The small parsers must consume every byte and reject unsupported code even after a valid handler statement, inside an unused method or outside the expected root/class. Incomplete parsing is not a restricted execution strategy.

## Model, DOM and host behavior

Compile the entire bundle before host read, component state creation, DOM changes or listener registration. Store immutable source-located models; instances own separate String state, properties, listeners and host callbacks. Caller public properties must exactly name all @api fields, contain bounded valid Strings and be copied before use; unknown/private keys fail. Explicit initializers remain source defaults for private state. A property update is an atomic partial patch to known public fields; it does not rerun connectedCallback or reset private edits. The developer harness must dispose/remount to switch record identity rather than patch recordId on an old host binding.

Mount creates an open shadow root on a harness-owned div and builds allowlisted nodes with createElement/createTextNode, safe static attributes and input.value properties. Dynamic data is always text/property data. Build detached nodes before publication. Subsequent field/property changes patch existing bindings; retain input DOM identity, focus and caret during typing. No document query, DOM access, native event object or browser capability is exposed to source. A container with an active mount or a foreign shadow root is rejected without mutation. Dispose removes the mounted subtree/listeners, is idempotent and invalidates later updates/dispatches without affecting another instance. A later mount may reuse the empty root created by this experiment, with a new instance/host owner; native shadow roots are not removed/re-attached.

Handlers evaluate against a staged copy of private state, charge before each action and prepare all text/property patches before publication. Runtime/budget/cancellation failures discard staged state, event queue and patches; restore the native edited input's value from prior state if its browser input event already changed it. A successful handler publishes state and DOM, then delivers at most one `save` event with copied primitive String detail to its bound trusted callback. This delayed delivery/atomic handler policy is synthetic and is not a claim about real LWC event ordering. A host denial after delivery leaves the successful local edit visible and the store unchanged; record that distinction rather than claiming end-to-end transactional rollback. Callback exceptions become bounded host diagnostics, never source execution.

The synthetic host copies records keyed structurally by tenant/ID and binds one explicit tenant/principal, record ID and read/Name-write policy per mounted session. Its read supplies public recordId/name; its save callback can only update Name on that captured record. Source event detail never chooses tenant, principal, record ID, field name or operation. Validate event shape/type/size and policy before replacing one record in the store; a denial or malformed event changes nothing. Reused IDs across tenants must remain separate. Missing/denied initial read mounts nothing. No API, persistence, real authentication, LDS/UI API wire adapter or permission-mode parity is supplied. Concurrent mounted instances have separate component state and host capabilities; cross-instance save delivery must be rejected, not routed by mutable DOM attributes or source properties. The trusted controller creates one opaque owner object per mount and its callback supplies that owner to the bound host; source can supply only event type/detail, never the owner. Closed bindings reject stale callbacks.

## Bounds and diagnostics

Defaults: BundleBytes=49152, FileBytes=16384, Tokens=4096 per file, Nesting=32, Fields=16, Methods=8 (including connectedCallback), Statements=64 total, TemplateNodes=128 (elements/text/binding nodes), StringBytes=4096, Steps=512 per mount/property update/handler, Events=1 per handler. TemplateNodes includes the outer template as one parsed element, even though it is not a rendered DOM element. Tokens counts scanner tokens per file: literal strings and contiguous markup text each count once; punctuation/binding tokens count individually; skipped formatting whitespace outside text and JS line comments do not count. Nesting counts structural delimiter/markup depth from one at the outer class/root. Statements counts assignments/dispatches across all methods, not field declarations. Every limit is a positive safe integer; Events must equal 1 (larger values are invalid-input), so this slice never publishes a multi-event action. API keys use the corresponding lower-camel-case names, such as bundleBytes and templateNodes. Bound complete UTF-8 input size before parsing/copying; charge token/depth/node/member/statement limits before retaining model data. Strings use UTF-8 bytes, not JavaScript code-unit length. Check source/data/host/event strings and concatenated rendered text before construction; concatenation is only renderer text assembly, never a source operator. Sources/props are bounded before copying. No recursive execution or unbounded traversal may bypass counters; lexical/parser nesting is explicitly guarded. Input/host sizes are trusted harness controls outside these finite experiment bounds; native DOM/allocation/time and aggregate heap isolation are not certified.

Cancellation uses AbortSignal checks before work and between parse/model/execution/render steps, with private per-invocation observer checkpoints for deterministic tests. Synchronous code cannot preempt an external task waiting on the browser event loop; do not claim arbitrary mid-instruction interruption. Disposal cancels later work. A late abort after publication cannot undo a delivered host save.

Diagnostics expose only code, phase, file tag and UTF-8 byte offset, never source/property/record values or raw parser exceptions. Codes: invalid-input, syntax, unsupported, invalid-model, type, denied, not-found, budget, cancelled, disposed, host. Phases: input, metadata, script, template, mount, update, handler, host. File tags: html, js, metadata, none. Input/host/disposed errors use none/-1; source-related failures point within the corresponding original source, and runtime errors use the invoking method/binding location. Missing fields/cardinality/name/reference errors are invalid-model; unknown constructs are unsupported; malformed lexical nesting is syntax. No Salesforce wire-error claim.

## Required experiments and decision

| Experiment | Mandatory assertions |
| --- | --- |
| Unchanged source to interactive DOM | Parse one independently authored account editor bundle; same source hashes render different synthetic name/record inputs. Typing updates its private draft and bound text; click emits exact save detail and host changes only the bound row's Name. |
| Public/private state and lifecycle | Required public props, unknown/private keys, one connectedCallback, partial public update without private reset, ordered assignments; two instances share neither state nor listeners. |
| Browser usability | Real Chromium keyboard focus/caret survives successive input updates, accessible textbox/button names exist, literal HTML/script-shaped strings display as text, and disposing one instance leaves the other usable. No screenshot-only assertions. |
| Host boundary | Same IDs across tenants, allowed/denied reads/writes, missing record, malformed/wrong-instance/oversized event and stale disposed callback; compare complete stores, not just changed Name. A denial preserves local edits but never changes records. |
| Complete rejection | Unknown metadata, namespace/extra files, unsupported template attributes/tags/directives, extra JS imports/calls/globals/decorators, unused bad methods and trailing source all reject before host read, DOM or listeners; no fixture-name special cases. |
| Bounded failure | Every limit exactly at/over boundary, invalid safe integers/UTF-8/surrogates, excessive nesting, oversized input/render/event data, steps/event budget failures after staged assignments; no partial state, DOM or queued event publication. |
| Cancellation/disposal | Pre-cancel, deterministic abort during parsing/handler preparation, abort before publication, repeated disposal and late event attempts; no partial effects or stale host write. |
| Repeatability/isolation | Every deterministic case twice with fresh host/state and unchanged source bytes; same compiled model reused for independent instances; later updates/events in one cannot affect the other. |

The fixture's public fields are recordId/name; private draft starts empty and connectedCallback assigns it from name. The template displays name and draft, wraps a text input in a label, and has a Save button.
